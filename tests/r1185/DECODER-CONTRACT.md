# E2 post-capture decoder contract

This is unexecuted R-owned equipment text. The C target STOP is active. No
actual guest C/AST has been generated or used to calibrate this decoder.

`Decoder` receives only the observer map (derived from real C/AST) and raw
passive stderr. It never receives the oracle or case ID. It selects roles by
actual typed declarations, statements, child relations, scalar Copy edges,
direct fixed-field lvalues, actual branch/loop structure and observed event IDs.
Only after decoding returns does `main` open the frozen oracle and select the
case for numeric comparison. No expected value selects a C variable or event.

The finite initial recognizer accepts an inlined normal-u8 IF join, one plain
while/infinite-for loop with an outer IF and actual Break, one selected-field
store, immutable pointer/address aliases, and explicit scalar declarations /
Copy paths. One unique scalar Copy assignment preceding a read can extend a
Copy chain; a future backedge write is not used as the current read's origin.
No general alias/liveness/scope solver is provided. A nonempty C for header,
do-loop, out-of-line helper layout, ambiguous role, escaped/reassigned pointer,
missing declaration event or optimized-away required relation remains
R_DECODER_INCOMPLETE. It is not automatically a compiler defect.

Decoded loop evidence includes phase headers and guard outcomes, the actual
C helper comparison operand path from carry, IF choices and normal-u8 join
results, caller Copy paths, existing guest old-load/result Copies, original
store lvalue address and incoming value, post-store selected/sibling values,
Continue carry writes, actual Break/loop result, outside result and phase
Copies, post-loop loads, and entry field Copies read at the Break boundary.
Original C root/selected/sibling/immutable alias addresses are compared within
one passive run. No root-versus-first-child address inequality or cross-run
address equality is asserted. C field declaration order is not equated with
NewLang field identity or a canonical ABI; source-issued public field facts
and the native member path remain separately available evidence.

For the ordinary control, the scalar Copy origin of the helper operand and
the post-helper Copy path from that origin must be structurally identified.
Helper-only results never imply any loop or root/store evidence.

The numeric `fresh_formal_values` comparison in the inlined case is explicitly
an inference through the observed C operand Copy path, together with separately
recorded source-issued public call/body facts. It is not a claim of a physical
callee frame, machine CALL, distinct native formal address or a runtime ghost
incarnation. Those semantic and machine notions must stay separate in reports.

Likewise STORE markers identify boundaries of the actual original C assignment.
They do not prove that GCC/Clang retained a physical STORE instruction after
optimization. In particular same-bits replacement has actual C flow/value/
address evidence, but physical instruction survival remains NOT_MEASURED unless
separate genuine machine evidence is later obtained under the release.

Return codes are 0 for the decoded finite numeric/identity comparisons matching,
1 for incomplete equipment/observability, and 42 for a supported decoded value
or within-run identity mismatch. The driver preserves every result and raw
artifact. It must not turn an unknown role, missing raw evidence, early source
rejection or absent public validator into PASS. A mismatch is affected STOP
to C, not permission to edit source/oracle or to declare general unsoundness.

No result, formatter/build success, CLI applicability, native address, optimized
machine operation, sanitizer behavior or audit-locality gain is established by
this text. The first actual generated shape can expose an R recognizer gap;
only an authorized mechanical repair with original evidence/version retention
may address it. V1/V2 values and source bytes stay fixed.
