## Supported file contract

Tested host lane: Linux x86_64 / POSIX2008, also intended for the project's WSL2
Ubuntu host lane. Native Windows and arbitrary network/concurrent filesystems
are not covered. Compiler and source semantics/issuer/proofs are unchanged.

The source must be a readable regular file (a source symlink is allowed). The
destination parent directory must already exist. Its path is resolved once with
`realpath` against the process cwd, which the compiler never changes. Parent
symlinks resolve to that directory; final destination symlinks (including dangling
ones), directories, special files, empty/`.`/`..` leaves and any device/inode alias
of SOURCE are refused with **CLI1 `V0-C-FILE`**. The check is repeated just before
commit. Exact, relative/parent aliases, symlink and hardlink source aliases cannot
clobber SOURCE in this supported stable-filesystem lane.

An unpredictable, exclusively created `mkstemp` sibling `OUTPUT.tmp.XXXXXX`
receives the exact existing shared compiler output. It is private mode0600
subject to the caller's umask; existing target permissions/ownership/ACLs are
not copied, and hardlinks to the previous target keep the old inode. If the
longer temporary leaf exceeds filesystem filename limits, fail safely; there is
no predictable-temp fallback. After successful emission **and fflush and fclose**,
same-directory `rename` atomically replaces the pathname. A writable directory
can permit replacement of a read-only regular file under ordinary POSIX rules;
this option is explicit replacement, not a file-mode-preservation facility.

On semantic CLI3, valid-but-unsupported backend CLI4, or caught open/write/flush/
close/rename CLI1 failure, the previous target remains unchanged and the staged
file is closed/unlinked. Normal semantic/backend diagnostics are preserved;
destination preparation can fail1 before source checking starts. If the filesystem
itself refuses unlink, the compiler reports **`V0-C-FILE-CLEANUP`** and the exact
remaining temporary pathname; it cannot promise removal despite filesystem refusal.
An absent final target stays absent on failed compilation. New mode emits no C
on stdout. Default stdout/pipe output remains nontransactional (`/dev/full`1).

The guarantee is **atomic pathname replacement visibility**, not fsync/power-loss
durability, signal/crash cleanup, protection against hostile concurrent directory/
source/target mutation, or arbitrary cross-filesystem/remote-FS transaction.
Keep source and destination paths stable during invocation. There is no privileged
filesystem service, chdir, shell command, guest I/O, FFI or external ABI change.
