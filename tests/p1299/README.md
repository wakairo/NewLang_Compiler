# Post-H Copy into a named stateful callee

The independent source retains `Display panel` before H0/H1/H2. It passes the
completed match's real u8 result through ordinary bindings into a named function
inside a scoped write loan. That callee updates the actual original field and
returns its old u8; the caller reads postcurrent and the unchanged sibling.

Adopted P1295 already supplies a finite technical USER-CLI-1 route using direct
replace. The additional capability here is author-defined callee/caller effect
and result composition. A pure helper or direct replace is a cheaper control but
does not exercise that boundary. Neither increment establishes a protected safe
library, general soundness, Product GO or comparative UB audit/re-audit locality.

Both genuine caller fragments already have existing public Copy body,
parameters and event proofs. The private C17 consumer retains the nested
issuer/entry and schedules one exact main postmatch call. It binds the latter to
the existing unchanged-prefix original, both current children and a closed H
entry. The existing public actual/formal, field, loan, old-result and handoff
checks do the rest. Per-caller budgets stay separate. No issuer, semantic world,
owner/Domain right, source law, ABI or general CFG is introduced.

The finite profile has one literal two-u8 prefix original immediately before the
typed H match, one existing nested Copy caller, and one root postmatch call with
the existing single-Change/old-result body profile. Arbitrary call graphs,
intervening state effects, changed-memory joins, multiple surviving roots and
loops remain outside this admission. Source spelling and literal values are not
Production selectors.

The two complete source negatives refuse a callee parameter-mode mismatch and
an omitted H1 allocation discharge. Public proof/real-node controls, original
prefix identity, unrestored A/foreign B canonical destruction, strict untouched
C then passive native H0/H1/H2, fresh bounded OOM, rollback and named-output
no-clobber are registered. The compatibility check compares live generated C
against adopted-main outputs for five unchanged unit/typed/direct paths. It is
a functional regression, not a historical SHA-generation protocol.
